Just In Case

web app · digital legacy shipped · live
33 sections · 11 groups 7,468 lines of strict TypeScript zero backend · zero network calls
open the live app ↗ repo private

A browser-only worksheet where you record where all your money actually is — accounts, EPF, insurance, property, nominees — so that if you weren't here, your family could find it.

The wedge: the obvious alternative is a password manager's emergency access — a vault that hands over the keys. This is a pointer map that is architecturally incapable of becoming a vault: a guard scans every schema key, label, and help text for credential patterns and refuses to boot the app if one appears. Holding the file lets your family find everything and touch nothing.

for the developers: one 1,587-line schema file drives every section, editor, list view, the gaps dashboard, and the JSON/PDF round-trip — adding a section is a data change to one file. connect-src 'none' in the CSP, so "no network calls" is enforced by the browser, not promised in a README.

⚑ the guard even rejects help text that mentions passwords — the warning about the rule had to move where the scanner can't reach. the rule outranks the reminder about the rule.

claudemeter

chrome extension · developer tool shipped · daily use
117 tests green on CI zero dependencies, runtime or dev MV3 · vanilla ES modules
repo private · runs unpacked walkthrough on request

Keeps your Claude usage on screen at all times — in the toolbar, or in a small window floating above every app — so "do I push on, or wrap up?" never costs four clicks again.

The wedge: every competing floating widget ships a native binary. claudemeter floats over your editor and terminal via the Document Picture-in-Picture API while staying an ordinary Chrome extension — and it reads the whole usage response, picking the headline by shortest runway, not fullest bar.

for the developers: polling once a minute builds a local history; a least-squares fit turns it into "~1h 30m of runway" — and the forecast refuses to answer across window resets or thin data rather than inventing a number. Most of the history tests assert the refusals, not the happy path.

⚑ it caught its own worst bug — a 1% reading rendering as "100% used" — because the number was on screen next to claude's own settings page, visibly disagreeing.

FlexCal

web app · scheduling building · pre-beta
5/5 milestones shipped 46 tests · 18 SQL migrations backend live on Supabase cloud
code, open source ↗

A booking link where clients propose three ranked times instead of grabbing one — and the internal meetings you'd happily move stay bookable instead of blocking your calendar.

The wedge vs Calendly / cal.com: an internal 1:1 and a client call are not the same kind of busy. Hosts approve one of three ranked proposals — each annotated with what saying yes costs ("would bump 2 blocks, 6 people notified") — and bumpable priority blocks keep malleable meetings bookable, with approval.

for the developers: double-booking is impossible by construction — a Postgres GiST exclusion constraint over the host's time range, not application code. No service-role key anywhere: seven SECURITY DEFINER functions are the entire public API, and anon has zero table access — verified live.

⚑ a live sync test fetched a google holiday calendar: 524 events parsed, exactly zero imported — every one said "show me as free". the parser was right for a reason that only looks like a bug.

How I think about building

    
Five opinions, each one paid for.

    

      

        01
        

          
Insight that isn't actionable is decoration.

          
At Media.net I inherited a reporting dashboard agencies loved but couldn't act on. Instead of adding charts, I rebuilt it so a flagged ad was one click from fixed — rules find the underperformers, bulk actions push straight back to the ad networks. Analytics products should close the loop from insight to action, or they're wallpaper.

        

      

      

        02
        

          
Enforce standards at authoring time, not by policy.

          
Wiki specs get ignored; validated contracts can't be. That's the data-contract platform's whole idea — dropdowns and generated snippets instead of documents people skip. The same instinct runs through Just In Case: a rule the app enforces by refusing to boot beats a warning nobody reads.

        

      

      

        03
        

          
The model isn't the product. The legible artifact is.

          
MMM output is coefficients and equations; the users were marketers and finance people. The PM's job with AI was never the model — it's translating what the model says into something a stakeholder can act on: a budget sheet, a forecast, a conversation that ends in a product page.

        

      

      

        04
        

          
Nothing ships unread.

          
My build system has no autopilot. I fire every command myself, and I read every phase before it merges — reviews, migrations, the security model. I ship this code, so I intend to understand this code.

        

      

      

        05
        

          
Building isn't the bottleneck anymore. Distribution is.

          
AI collapsed the cost of shipping — the products above took evenings, not funding rounds. The scarce skills now are knowing what's worth building and getting it into people's hands. That's a product problem, which is rather convenient for a product manager.
